# 0001. Record architecture decisions

- Status: Accepted
- Date: YYYY-MM-DD

## Context

Decisions about structure and tooling are made in chat and meetings, and the reasoning is lost when people move on.

## Options considered

- Keep decisions in a wiki.
- Keep decisions in the repository as short records.
- Do nothing.

## Decision

We keep one short record per significant decision in `docs/adr/`, reviewed through pull requests.

## Consequences

- New contributors can learn why the system looks as it does.
- Writing a record adds a small cost to each significant decision.
- Old records are superseded, never edited into agreement.
