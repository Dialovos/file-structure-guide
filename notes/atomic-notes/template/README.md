# Atomic notes — template

A worked illustration of the atomic-note rule, with two passing
examples and one counter-example. See `../GUIDE.md` for the full
reasoning.

## Files

- **`good-atomic-note-1.md`** — *Attention residue is a tax on context
  switching.* One mechanism, citable in full, has sources. Passes the
  embeddability test.
- **`good-atomic-note-2.md`** — *Atomic notes should be embeddable.*
  Defines the test for atomicity itself. Meta but still atomic — one
  idea (the embeddability test).
- **`bad-bundled-note.md`** — *Productivity thoughts.* Five distinct
  ideas bundled under a topic-shaped title. The HTML comment at top
  explains why it fails the rule and how to fix it.

## The rule, restated

> One note = one idea, small enough to be embedded fully into another
> note without dragging in irrelevant material or losing load-bearing
> context.

The unit is the **idea**, not the word count. A 1,500-word note on a
single mechanism is atomic. A 200-word "thoughts" bundle is not.

## How to use this template

1. Read the two good notes. Notice that each title is a *claim* or a
   *named phenomenon*, not a topic.
2. Read the bad note's top-of-file comment, then read the prose. Try
   to mentally split it into five atomic notes (the comment lists
   them).
3. Apply the embeddability test on your own notes: can you quote each
   one in full somewhere else?

## Where atomicity belongs

- **Knowledge layer (apply the rule):** durable notes you'll cite,
  link, and re-edit over years.
- **Capture layer (don't apply the rule):** daily journal, fleeting
  thoughts, meeting notes. Bundle freely; atomize during refinement.
- **Drafts layer (don't apply the rule):** work-in-progress prose
  is allowed to be as long as it needs to be.
